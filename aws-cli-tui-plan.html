Build the safe half first

The first release is intentionally narrow: discovery and read operations across AWS, with the same “run bare for a guided terminal experience” pattern used by AgentCore CLI.

Release 0.1

The catalog includes public service models and exposes zero-required-input List* operations plus Get* and Describe*. Selecting List runs immediately. Smithy pagination traits drive one page view at a time, while continuation tokens remain internal.

  • Use one fuzzy, typo-tolerant no-space search token across normalized resource, action, and operation names.
  • Normalize both sides to lowercase ASCII letters and digits: ListAgentRuntimes → listagentruntimes.
  • Keep AWS service IDs as hidden routing metadata rather than a navigation level.
  • Open List with no parameter screen and move through API pages with Next/Previous.
  • Generate input forms only for standalone Get/Describe operations that need identifiers.
  • Fuzzy-filter only the rows already loaded on the current API page.
  • Render Get results as syntax-colored, pretty-printed JSON with selectable ARN values.
  • Respect profile, region, endpoint, retry, and credential behavior from AWS CLI v2.
  • Resolve ARN links from the current public Smithy models on GitHub and open the target resource when unambiguous.

Explicit boundary

No create, update, delete, invoke, streaming, waiter, interactive auth, server-side List parameters, or “fetch all” mode in 0.1. List operations with required inputs are excluded. Unknown output shapes always fall back to pretty JSON.

One core, two interfaces

Commander remains a thin adapter. The TUI and headless commands invoke the same catalog, validation, execution, and rendering classes. 

awstui

Launch the guided terminal UI. This mirrors AgentCore CLI’s no-argument terminal entry pattern. 

awstui list [search]

Open the global search restricted to zero-required-input List* actions. Search is one fuzzy token with no spaces, such as agentruntime, agentruntmie, or listagentruntimes. Exact normalized matches rank first; a unique match runs immediately and multiple matches open the picker. 

awstui get [search]

Open the same fuzzy no-space search restricted to Get* and Describe*. After selection, the generated input view asks only for identifiers required by that action. 

awstui models update
awstui models doctor

Refresh the pinned public model snapshot and report unsupported traits or naming collisions. Update is explicit; normal browsing never requires network access. 

global:
--profile --region --endpoint-url
--output --query --no-color --debug

Keep session flags consistent across the root command, TUI, list, and get. Avoid operation-specific global behavior.

Smithy supplies the map

The packaged public-model catalog drives discovery and forms. ARN drill-through checks the current public models on GitHub at runtime. AWS CLI v2 performs signing, credential resolution, protocol serialization, retries, and endpoint behavior.

Key abstractions

Use TypeScript type aliases for generated/data-only shapes such as OperationEntry, ServiceEntry, and InputField. Each search entry carries friendly text for the user and hidden backend routing. Cohesive stateful behavior lives in SmithyCatalog, GithubSmithyRepository, ArnReferenceResolver, and AwsCliExecutor.

ARN resolution boundary

The resolver only executes when a user activates an ARN. It refreshes the source and target model paths from GitHub with If-None-Match, prefers an explicit aws.api#arnReference and Smithy resource read operation, then falls back to an exact Get/Describe match only when the mapping is unambiguous.

Four build slices

Each slice exits with something runnable. The catalog and executor prove the difficult parts before terminal polish expands.

  1. Catalog compiler

    Pin a commit from aws/api-models-aws; resolve JSON AST references; classify List/Get/Describe; emit a compact deterministic manifest and diagnostics.Exit: snapshot tests cover S3, DynamoDB, STS, and both AgentCore services; repeated generation produces identical bytes.

  2. Headless commands

    Build Commander registration, fuzzy no-space action search, shared AWS options, shape-aware Get input parsing, safe child process execution, single-page List execution, JSON output, and error mapping.Exit: both awstui list agentruntime and typo awstui list agentruntmie resolve without service/API parameters; ambiguous tokens open the picker.

  3. Terminal browser

    Add Ink screens, global and current-page fuzzy filtering, keyboard navigation, one-view-per-page List navigation, generated Get input editor, result table projection, pretty JSON detail, ARN selection, and resize handling.Exit: Next loads one API page, Previous returns to the cached prior page, and the workflow works at 80×24 and 140×45.

  4. Hardening and release

    Add redaction, cancellation, timeouts, model doctor, packaged catalog, update policy, telemetry decision, CI across Node 20/22, and npm packaging.Exit: install globally, launch with no args, and complete the acceptance checklist below.

Hard parts worth naming

The difficult work is model interpretation and generic output projection, not drawing panes.

Risk Plan Proof
A service model changes daily Pin the search catalog for deterministic packaging, but conditionally fetch current source/target model files whenever an ARN is opened. Tests prove every load reaches GitHub and unchanged files reuse the cached ETag response.
A search token can contain typos or match multiple actions Strip spaces, hyphens, underscores, and case from indexed names. Rank exact, prefix, and substring matches first, followed by bounded edit-distance and ordered-subsequence matches. Ambiguous results stay in the picker. Golden ranking cases cover exact agentruntime, typo agentruntmie, abbreviation agntrntm, and unrelated-token rejection.
Hidden backend routing must be deterministic Each generated search entry stores one canonical operation ID and AWS CLI command separately from its public Smithy model directory. For example, the model path is dynamodb-streams, while execution uses aws dynamodbstreams. Service names never need user selection. Doctor checks every route against aws help when AWS CLI is available.
Generic list output has no obvious columns Score scalar members: identifiers/names first, then status/type/time; cap width and retain JSON fallback. Golden projections across at least 20 structurally different services.
Some List operations require scope inputs Exclude them from 0.1 rather than adding a List parameter form. Report the reason in model doctor output. The catalog marks every omitted List operation and its required members.
Get inputs include nested unions and blobs 0.1 supports scalar, enum, list-of-scalar, and simple structures; complex fields accept JSON with model-aware validation. Unsupported editor modes are visible before execution and accept pasted JSON.
An ARN can map to multiple resources or reads Prefer explicit Smithy service/resource references, resource ARN templates, and resource identifiers. Refuse tied top candidates instead of guessing. Resolver tests cover explicit cross-service resource reads, IAM fallback, ARN capture, and ambiguous-result rejection.
Secrets leak through history or logs Never invoke a shell; pass argv directly; mark sensitive Smithy members; redact command previews, debug logs, and errors. Tests assert sensitive values never appear in snapshots or thrown errors.
AgentCore may lead AWS CLI availability Report “model known, executor unavailable” clearly. Keep the executor contract ready for a generated AWS SDK pack. Doctor distinguishes missing operation from auth, region, and service errors.
